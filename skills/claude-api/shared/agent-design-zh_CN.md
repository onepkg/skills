# 智能体设计模式

本文档涵盖在 Claude API 上构建智能体的决策启发式方法：选择哪些原语、如何设计工具接口，以及在长时间运行中如何管理上下文和成本。有关各工具的具体机制和代码示例，请参阅 `tool-use-concepts.md` 和各语言专属文件夹。

---

## 模型参数

| 参数 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **自适应思考** (`thinking: {type: "adaptive"}`) | 当你希望 Claude 自主控制何时思考以及思考多深时。 | Claude 根据每个请求决定思考深度，并在工具调用之间自动穿插思考。无需调整令牌预算。 |
| **精力** (`output_config: {effort: ...}`) | 当需要在全面性和令牌效率之间进行权衡时。 | 较低精力 → 更少且更整合的工具调用，更少的前缀说明，更简洁的确认。`medium` 通常是较好的平衡点。当正确性比成本更重要时使用 `max`。 |

参见 `SKILL.md` §思考与精力，了解模型支持和参数详情。

## 设计工具接口

### Bash 工具与专用工具

Claude 不知道你的应用程序的安全边界、审批策略或用户体验界面。Claude 发出工具调用；你的执行器负责处理这些调用。这些工具调用的形状决定了执行器能做什么。

**Bash 工具**为 Claude 提供了广泛的程序性杠杆——它几乎可以执行任何操作。但它只给执行器提供一个不透明的命令字符串，每个操作的形状都相同。将操作提升为**专用工具**则为执行器提供了一个特定于操作的钩子，带有类型化的参数，可以拦截、门控、渲染或审计。

**何时将操作提升为专用工具：**

- **安全边界。** 需要门控的操作是自然的候选对象。可逆性是一个有用的标准：难以逆转的操作（外部 API 调用、发送消息、删除数据）可以置于用户确认之后。`send_email` 工具易于门控；`bash -c "curl -X POST ..."` 则不然。
- **陈旧性检查。** 专用 `edit` 工具可以在文件自上次读取后发生变化时拒绝写入。Bash 无法强制保证这一不变性。
- **渲染。** 某些操作受益于自定义界面。Claude Code 将提问功能提升为工具，以便将其渲染为模态框、呈现选项，并在回答前阻塞智能体循环。
- **调度。** `glob` 和 `grep` 等只读工具可以标记为并行安全。当相同的操作通过 Bash 运行时，执行器无法区分并行安全的 `grep` 和并行不安全的 `git push`，因此必须串行化。

**经验法则：** 从 Bash 开始以获得广度。当需要对操作进行门控、渲染、审计或并行化时，再提升为专用工具。

## Anthropic 提供的工具

| 工具 | 端 | 使用时机 | 预期效果 |
| --- | --- | --- | --- |
| **Bash** | 客户端 | Claude 需要执行 shell 命令。 | Claude 发出命令；你的执行器执行它们。提供参考实现。 |
| **文本编辑器** | 客户端 | Claude 需要读取或编辑文件。 | Claude 通过你的实现查看、创建和编辑文件。提供参考实现。 |
| **计算机使用** | 客户端或服务端 | Claude 需要与 GUI、Web 应用或可视化界面交互。 | Claude 截取屏幕截图并发出鼠标/键盘命令。可自托管（你运行环境）或由 Anthropic 托管。 |
| **代码执行** | 服务端 | Claude 需要在你不想管理的沙箱中运行代码。 | Anthropic 托管的容器，内置文件和 bash 子工具。无客户端执行。 |
| **Web 搜索/获取** | 服务端 | Claude 需要获取超出其训练截止日期的信息（新闻、时事、近期文档）或特定 URL 的内容。 | Claude 发出查询或 URL；Anthropic 执行并返回带引用的结果。 |
| **记忆** | 客户端 | Claude 需要在会话间保存上下文。 | Claude 读取/写入 `/memories` 目录。你实现存储后端。 |

**客户端**工具由 Anthropic 定义（名称、架构、Claude 的使用模式），但由你的执行器执行。Anthropic 提供参考实现。**服务端**工具完全在 Anthropic 基础设施上运行——在 `tools` 中声明即可，其余由 Claude 处理。

## 组合工具调用：程序化工具调用

使用标准工具调用时，每次工具调用都是一次往返：Claude 调用工具，结果进入 Claude 的上下文，Claude 对其进行推理，然后调用下一个工具。三个顺序操作（读取个人资料 → 查找订单 → 检查库存）意味着三次往返。每次都会增加延迟和令牌，并且大多数中间数据之后不再需要。

**程序化工具调用（PTC）** 让 Claude 改为将这些调用组合成一个脚本。脚本在代码执行容器中运行。当脚本调用工具时，容器暂停，调用被执行（客户端或服务端），结果返回到正在运行的代码——而不是 Claude 的上下文。脚本使用正常的控制流（循环、过滤、分支）处理结果。只有脚本的最终输出返回给 Claude。

| 使用时机 | 预期效果 |
| --- | --- |
| 多个顺序工具调用，或希望在中间结果进入上下文窗口之前对其进行过滤的大型中间结果。 | Claude 编写将工具作为函数调用的代码。在代码执行容器中运行。令牌成本与最终输出成正比，而非中间结果。 |

## 扩展工具和指令集

| 功能 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **工具搜索** | 可用工具很多，但每个请求只有少数相关。不希望将所有 schema 都预先加载到上下文中。 | Claude 搜索工具集并仅加载相关的 schema。工具定义被追加而非替换——保留缓存（参见下文缓存部分）。 |
| **技能** | 任务特定的指令，Claude 应仅在相关时加载。 | 每个技能是一个包含 `SKILL.md` 的文件夹。技能描述默认位于上下文中；当任务需要时，Claude 读取完整文件。 |

两种模式都保持固定上下文较小，并按需加载细节。

## 长时间运行的智能体：管理上下文

| 模式 | 使用时机 | 预期效果 |
| --- | --- | --- |
| **上下文编辑** | 上下文在多轮对话后变得过时（旧的工具结果、已完成的思考）。 | 工具结果和思考块根据可配置的阈值被清除。在不进行摘要的情况下保持记录精简。 |
| **压缩** | 对话可能达到或超过上下文窗口限制。 | 较早的上下文被汇总为一个压缩块（服务端完成）。请参见 `SKILL.md` §压缩，了解关键的 `response.content` 处理方式。 |
| **记忆** | 状态必须在会话间持久化（不仅仅是在一次对话中）。 | Claude 在记忆目录中读取/写入文件。在进程重启后仍然存在。 |

**如何选择：** 上下文编辑和压缩在会话内运行——编辑会修剪过时的轮次，压缩会在接近限制时进行摘要。记忆用于跨会话持久化。许多长时间运行的智能体会同时使用这三种方式。

## 智能体的缓存

**首先阅读 `prompt-caching.md`。** 它涵盖了前缀匹配不变性、断点放置、静默失效审计，以及为什么在会话中更改工具或模型会破坏缓存。本节仅涵盖针对这些约束的智能体特定解决方法。

| 约束（来自 `prompt-caching.md`） | 智能体特定解决方法 |
| --- | --- |
| 在会话中编辑系统提示会使缓存失效。 | 改为在 `messages` 数组中追加一个 `<system-reminder>` 块。缓存的前缀保持不变。Claude Code 使用此方法进行时间更新和模式切换。 |
| 在会话中切换模型会使缓存失效。 | 为子任务使用较便宜的模型生成**子智能体**；主循环保持在一个模型上。Claude Code 的 Explore 子智能体使用 Haiku 来实现这一点。 |
| 在会话中添加/删除工具会使缓存失效。 | 使用**工具搜索**进行动态发现——它追加工具 schema 而非替换它们，因此现有前缀得以保留。 |

对于多轮断点放置，使用顶级自动缓存——参见 `prompt-caching.md` §放置模式。
