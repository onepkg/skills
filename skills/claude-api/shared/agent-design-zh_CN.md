# 智能体设计模式

本文件介绍在 Claude API 上构建智能体的决策启发式方法：使用哪些原语、如何设计工具界面以及如何在长期运行中管理上下文和成本。有关每个工具的机制和代码示例，请参阅 `tool-use-concepts.md` 和特定语言的文件夹。

---

## 模型参数

| 参数 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **自适应思考**（`thinking: {type: "adaptive"}`） | 当您希望 Claude 控制何时以及思考多少时。 | Claude 按请求确定思考深度，并自动在工具调用之间交错思考。无需调整令牌预算。 |
| **努力程度**（`output_config: {effort: ...}`） | 当调整彻底性和令牌效率之间的权衡时。 | 较低的努力程度 → 更少且更整合的工具调用、更少的前言、更简洁的确认。`medium` 通常是一个有利的平衡点。当正确性比成本更重要时使用 `max`。 |

请参阅 `SKILL.md` § 思考与努力程度 了解模型支持和参数详细信息。

## 设计您的工具界面

### Bash vs. 专用工具

Claude 不知道您的应用程序的安全边界、批准策略或 UX 界面。Claude 发出工具调用；您的 harness 处理它们。这些工具调用的形状决定了 harness 可以做什么。

**Bash 工具** 给 Claude 广泛的程序化影响力 — 它可以执行几乎任何操作。但它只给 harness 一个不透明的命令字符串，每个操作的形状都相同。将操作提升为**专用工具**会给 harness 一个特定于操作的钩子，带有它可以拦截、控制、渲染或审计的类型化参数。

**何时将操作提升为专用工具：**

- **安全边界。** 需要控制的操作是自然的候选者。可逆性是一个有用的标准：难以逆转的操作（外部 API 调用、发送消息、删除数据）可以在用户确认后进行控制。`send_email` 工具易于控制；`bash -c "curl -X POST ..."` 则不行。
- **陈旧性检查。** 专用的 `edit` 工具可以在文件自 Claude 上次读取以来发生变化时拒绝写入。Bash 无法强制执行该不变量。
- **渲染。** 某些操作受益于自定义 UI。Claude Code 将提问提升为工具，以便它可以渲染为模态、呈现选项并阻塞智能体循环直到得到答复。
- **调度。** 像 `glob` 和 `grep` 这样的只读工具可以标记为并行安全。当相同的操作通过 bash 运行时，harness 无法区分并行安全的 `grep` 和并行不安全的 `git push`，因此它必须序列化。

**经验法则：** 从 bash 开始以获得广度。当您需要控制、渲染、审计或并行化操作时，提升为专用工具。

## Anthropic 提供的工具

| 工具 | 端 | 何时使用 | 预期效果 |
| --- | --- | --- | --- |
| **Bash** | 客户端 | Claude 需要执行 shell 命令。 | Claude 发出命令；您的 harness 执行它们。提供参考实现。 |
| **文本编辑器** | 客户端 | Claude 需要读取或编辑文件。 | Claude 通过您的实现查看、创建和编辑文件。提供参考实现。 |
| **计算机使用** | 客户端或服务器 | Claude 需要与 GUI、Web 应用程序或视觉界面交互。 | Claude 截取屏幕截图并发出鼠标/键盘命令。可以自托管（您运行环境）或 Anthropic 托管。 |
| **代码执行** | 服务器 | Claude 需要在您不想管理的沙箱中运行代码。 | 带有内置文件和 bash 子工具的 Anthropic 托管容器。无客户端执行。 |
| **网络搜索 / 获取** | 服务器 | Claude 需要超过其训练截止时间的信息（新闻、时事、最近文档）或特定 URL 的内容。 | Claude 发出查询或 URL；Anthropic 执行它并返回带引用的结果。 |
| **记忆** | 客户端 | Claude 需要跨会话保存上下文。 | Claude 读取/写入 `/memories` 目录。您实现存储后端。 |

**客户端** 工具由 Anthropic 定义（名称、架构、Claude 的使用模式），但由您的 harness 执行。Anthropic 提供参考实现。**服务器端** 工具完全在 Anthropic 基础设施上运行 — 在 `tools` 中声明它们，Claude 会处理其余部分。

## 组合工具调用：程序化工具调用

使用标准工具使用时，每个工具调用都是一次往返：Claude 调用工具，结果进入 Claude 的上下文，Claude 对其进行推理，然后调用下一个工具。三个连续操作（读取配置文件 → 查找订单 → 检查库存）意味着三次往返。每次都会增加延迟和令牌，并且大多数中间数据永远不再需要。

**程序化工具调用（PTC）** 让 Claude 将这些调用组合成脚本。脚本在代码执行容器中运行。当脚本调用工具时，容器暂停，调用被执行（客户端或服务器端），结果返回到运行的代码 — 而不是 Claude 的上下文。脚本使用正常控制流（循环、过滤器、分支）处理它。只有脚本的最终输出返回到 Claude。

| 何时使用 | 预期效果 |
| --- | --- |
| 许多连续工具调用，或您希望在到达上下文窗口之前过滤的大型中间结果。 | Claude 编写将工具作为函数调用的代码。在代码执行容器中运行。令牌成本随最终输出而扩展，而不是中间结果。 |

## 扩展工具和指令集

| 功能 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **工具搜索** | 可用工具很多，但每个请求只相关少数几个。不想在上下文中预先包含所有架构。 | Claude 搜索工具集并只加载相关架构。工具定义是追加的，不是交换的 — 保留缓存（见下文缓存）。 |
| **技能** | Claude 应仅在相关时加载的特定于任务的指令。 | 每个技能是一个带有 `SKILL.md` 的文件夹。技能的描述默认位于上下文中；当任务需要时，Claude 读取完整文件。 |

两种模式都保持固定上下文很小并按需加载细节。

## 长期运行的智能体：管理上下文

| 模式 | 何时使用 | 预期效果 |
| --- | --- | --- |
| **上下文编辑** | 上下文在许多轮次后变得陈旧（旧工具结果、已完成的思考）。 | 工具结果和思考块根据可配置的阈值清除。保持转录精简而不进行摘要。 |
| **压缩** | 对话可能达到或超过上下文窗口限制。 | 较早的上下文在服务器端汇总为压缩块。请参阅 `SKILL.md` § 压缩 了解关键的 `response.content` 处理。 |
| **记忆** | 状态必须跨会话持久化（不仅仅在一个对话中）。 | Claude 在记忆目录中读取/写入文件。在进程重启后仍然存在。 |

**在它们之间选择：** 上下文编辑和压缩在一个会话内操作 — 编辑修剪陈旧的轮次，压缩在您接近限制时进行摘要。记忆用于跨会话持久化。许多长期运行的智能体使用全部三个。

## 智能体的缓存

**首先阅读 `prompt-caching.md`。** 它介绍了前缀匹配不变量、断点放置、静默失效器审计，以及为什么在会话中途更改工具或模型会破坏缓存。本节仅介绍针对这些约束的智能体特定解决方法。

| 约束（来自 `prompt-caching.md`） | 智能体特定的解决方法 |
| --- | --- |
| 在会话中途编辑系统提示会使缓存失效。 | 改为在 `messages` 数组中追加一个 `<system-reminder>` 块。缓存的前缀保持不变。Claude Code 将此用于时间更新和模式转换。 |
| 在会话中途切换模型会使缓存失效。 | 为子任务生成一个使用更便宜模型的**子智能体**；保持主循环在一个模型上。Claude Code 的 Explore 子智能体就是这样使用 Haiku 的。 |
| 在会话中途添加/移除工具会使缓存失效。 | 使用**工具搜索**进行动态发现 — 它追加工具架构而不是交换它们，因此保留现有前缀。 |

对于多轮断点放置，请使用顶级自动缓存 — 请参阅 `prompt-caching.md` § 放置模式。
