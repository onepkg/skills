算法哲学是计算美学运动，通过代码表达。输出 .md 文件（哲学）、.html 文件（交互式查看器）和 .js 文件（生成算法）。

这分两步完成：
1. 算法哲学创作（.md 文件）
2. 通过创建 p5.js 生成艺术来表达（.html + .js 文件）

首先，承担以下任务：

## 算法哲学创作

首先，创建一个算法哲学（而非静态图像或模板），将通过以下方式诠释：
- 计算过程、涌现行为、数学之美
- 种子随机性、噪声场、有机系统
- 粒子、流动、场、力
- 参数化变化与受控混沌

### 关键理解
- 接收的内容：用户提供的一些微妙输入或指令，可作为基础，但不应限制创作自由。
- 创作的内容：一种算法哲学/生成美学运动。
- 接下来会发生什么：同一版本接收该哲学并"用代码表达它"——创建 p5.js 草图，其中 90% 为算法生成，10% 为基本参数。

考虑这种方式：
- 撰写一份生成艺术运动的宣言
- 下一阶段涉及编写赋予其生命的算法

哲学必须强调：算法表达。涌现行为。计算之美。种子变异。

### 如何生成算法哲学

**命名该运动**（1-2 个词）："有机湍流" / "量子和声" / "涌现静默"

**阐述哲学**（4-6 段——简洁但完整）：

要捕捉算法的精髓，请阐述该哲学如何通过以下方面体现：
- 计算过程和数学关系？
- 噪声函数和随机性模式？
- 粒子行为和场动力学？
- 时间演化和系统状态？
- 参数化变化和涌现复杂性？

**关键指导原则：**
- **避免冗余**：每个算法方面应只提及一次。避免重复关于噪声理论、粒子动力学或数学原理的概念，除非增加新的深度。
- **反复强调工艺水平**：哲学必须多次强调最终算法应看起来像是经过无数小时的开发、精心打磨，并出自领域顶尖人物之手。这一框架至关重要——重复使用诸如"精心打造的算法"、"深度计算专业知识的产物"、"苦心优化"、"大师级实现"等短语。
- **留出创作空间**：在算法方向上要具体，但也要足够简洁，使下一个 Claude 有空间在极高的工艺水平上做出诠释性的实现选择。

哲学必须引导下一个版本用算法的方式表达思想，而非通过静态图像。美存在于过程之中，而非最终画面。

### 哲学示例

**"有机湍流"**
哲学：受自然规律约束的混沌，从无序中涌现的有序。
算法表达：由分层 Perlin 噪声驱动的流场。数千个粒子跟随矢量力，其轨迹累积成有机密度图。多个噪声倍频程形成湍流区域和宁静地带。颜色由速度和密度决定——快速粒子燃烧明亮，慢速粒子淡入阴影。算法运行至平衡——精心调校的平衡，其中每个参数都经过无数次迭代，由一位计算美学大师精心打磨。

**"量子和声"**
哲学：表现出波动干涉模式的离散实体。
算法表达式：粒子在网格上初始化，每个粒子携带一个通过正弦波演化的相位值。当粒子靠近时，它们的相位相互干涉——相长干涉产生明亮节点，相消干涉产生空洞。简谐运动产生复杂的涌现曼陀罗图案。这是苦心频率校准的成果，每个比率都经过精心挑选以产生共鸣之美。

**"递归低语"**
哲学：跨尺度的自相似性，有限空间中的无限深度。
算法表达式：递归细分的分支结构。每个分支略微随机化，但受黄金比例约束。L-system 或递归细分生成既数学又有机的树状形态。微妙的噪声扰动打破完美对称。线条粗细随每一级递归递减。每个分支角度都是深度数学探索的产物。

**"场动力学"**
哲学：通过其对物质的影响而变得可见的不可见力。
算法表达式：由数学函数或噪声构建的矢量场。粒子在边缘诞生，沿场线流动，到达平衡或边界时消亡。多个场可以吸引、排斥或旋转粒子。可视化只显示轨迹——不可见力的幽灵般证据。一场通过力平衡精心编排的计算之舞。

**"随机结晶"**
哲学：随机过程结晶为有序结构。
算法表达式：随机圆填充或 Voronoi 镶嵌。从随机点开始，让它们通过松弛算法演化。细胞相互推离直至平衡。颜色基于细胞大小、邻居数量或距中心距离。由此产生的有机镶嵌既随机又必然。每个种子产生独特的晶体之美——大师级生成算法的标志。

*这些是简化的示例。实际的算法哲学应为 4-6 个内容丰富段落。*

### 基本原则
- **算法哲学**：创建一种通过代码表达的计算世界观
- **过程重于结果**：始终强调美产生于算法的执行过程——每次运行都是独一无二的
- **参数化表达**：思想通过数学关系、力、行为来传达——而非静态构图
- **艺术自由**：下一个 Claude 以算法方式诠释哲学——提供创作实施空间
- **纯生成艺术**：关乎创造"活的算法"，而非带有随机性的静态图像
- **专家工艺**：反复强调最终算法必须感觉是精心打造、经过无数次迭代打磨、由处于计算美学领域顶尖水平的深度专家打造的产物

**算法哲学应为 4-6 段。** 用诗意的计算哲学来表达，将预期愿景融为一体。避免重复相同的观点。将此算法哲学输出为 .md 文件。

**关键步骤**：在实现算法之前，识别原始请求中微妙的、概念性的线索。

**基本原则**：

### 技术要求

**种子随机性（Art Blocks 模式）**：
```javascript
// ALWAYS use a seed for reproducibility
let seed = 12345; // or hash from user input
randomSeed(seed);
noiseSeed(seed);
```

**参数结构——遵循哲学**：

要建立从算法哲学中自然涌现的参数，请思考："该系统的哪些特质可以调节？"

```javascript
let params = {
  seed: 12345,  // Always include seed for reproducibility
  // colors
  // Add parameters that control YOUR algorithm:
  // - Quantities (how many?)
  // - Scales (how big? how fast?)
  // - Probabilities (how likely?)
  // - Ratios (what proportions?)
  // - Angles (what direction?)
  // - Thresholds (when does behavior change?)
};
```

**要设计有效的参数，请关注系统需要可调的属性，而不是思考"模式类型"。**

**核心算法——表达哲学**：

**关键**：算法哲学应决定构建什么。

要通过代码表达哲学，避免思考"我应该使用哪种模式？"，而是思考"如何用代码表达这种哲学？"

如果哲学是关于**有机涌现**，考虑使用：
- 随时间积累或生长的元素
- 受自然规则约束的随机过程
- 反馈循环和交互

如果哲学是关于**数学之美**，考虑使用：
- 几何关系和比率
- 三角函数和和声
- 精确计算产生意外模式

如果哲学是关于**受控混沌**，考虑使用：
- 严格边界内的随机变化
- 分岔和相变
- 从无序中涌现有序

**算法源于哲学，而非选项菜单。**

为了指导实现，让概念本质为创意和原创选择提供信息。构建能表达本次特定请求愿景的作品。

**画布设置**：标准 p5.js 结构：
```javascript
function setup() {
  createCanvas(1200, 1200);
  // Initialize your system
}

function draw() {
  // Your generative algorithm
  // Can be static (noLoop) or animated
}
```

### 工艺要求

**关键**：要达到大师水准，创建的算法应让人感觉像是由一位大师级生成艺术家经过无数次迭代打磨而成。精心调校每一个参数。确保每种模式都带有目的性地涌现。这不是随机噪声——这是经过深度专业知识打磨的受控混沌。

- **平衡**：复杂度而不视觉杂乱，有序而不僵硬
- **色彩和谐**：深思熟虑的调色板，而非随机 RGB 值
- **构图**：即使在随机性中，也要保持视觉层次和流动
- **性能**：流畅执行，如果是动画则优化实时表现
- **可复现性**：相同种子始终产生相同输出

## 交互式产物创建

**提醒：`templates/viewer.html` 应该已经阅读过（见步骤 0）。使用该文件作为起点。**

为了允许探索生成艺术，创建一个自包含的单个 HTML 产物。确保该产物能在 claude.ai 或任何浏览器中立即使用——无需任何设置。将所有内容内联嵌入。

### 关键：固定部分 vs 可变部分

`templates/viewer.html` 文件是基础。它包含所需的确切结构和样式。

**固定部分（始终完全按照所示包含）：**
- 布局结构（头部、侧边栏、主画布区域）
- Anthropic 品牌标识（UI 颜色、字体、渐变）
- 侧边栏中的种子部分：
  - 种子显示
  - 上一个/下一个按钮
  - 随机按钮
  - 跳转到种子输入框 + 前往按钮
- 侧边栏中的操作部分：
  - 重新生成按钮
  - 重置按钮

**可变部分（为每个作品定制）：**
- 整个 p5.js 算法（setup/draw/classes）
- 参数对象（定义艺术所需的内容）
- 侧边栏中的参数部分：
  - 参数控件数量
  - 参数名称
  - 滑块的最小值/最大值/步长
  - 控件类型（滑块、输入框等）
- 颜色部分（可选）：
  - 某些艺术需要颜色选择器
  - 某些艺术可能使用固定颜色
  - 某些艺术可能是单色的（无需颜色控件）
  - 根据艺术需求决定

**每个作品都应有独特的参数和算法！** 固定部分提供一致的用户体验——其他一切表达独特的愿景。

### 必需功能

**1. 参数控件**
- 数值参数滑块（粒子数量、噪声缩放、速度等）
- 调色板颜色选择器
- 参数变化时实时更新
- 重置按钮恢复默认值

**2. 种子导航**
- 显示当前种子编号
- "上一个"和"下一个"按钮循环切换种子
- "随机"按钮生成随机种子
- 输入框跳转到特定种子
- 按需生成 100 个变体（种子 1-100）

**3. 单产物结构**
```html
<!DOCTYPE html>
<html>
<head>
  <!-- p5.js from CDN - always available -->
  <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0/p5.min.js"></script>
  <style>
    /* All styling inline - clean, minimal */
    /* Canvas on top, controls below */
  </style>
</head>
<body>
  <div id="canvas-container"></div>
  <div id="controls">
    <!-- All parameter controls -->
  </div>
  <script>
    // ALL p5.js code inline here
    // Parameter objects, classes, functions
    // setup() and draw()
    // UI handlers
    // Everything self-contained
  </script>

```

**关键**：这是单个产物。无外部文件、无导入（p5.js CDN 除外）。所有内容内联。

**4. 实现细节——构建侧边栏**

侧边栏结构：

**1. 种子（固定）** - 始终完全按照所示包含：

**2. 参数（可变）** - 为作品创建控件：
```html
<div class="control-group">
    <label>Parameter Name</label>
```

**3. 颜色（可选/可变）** - 如果作品需要可调节的颜色则包含：
- 如果用户应控制调色板，则添加颜色选择器
- 如果作品使用固定颜色，则跳过此部分
- 如果作品是单色的，则跳过

**4. 操作（固定）** - 始终完全按照所示包含：
- 重新生成按钮
- 重置按钮
- 下载 PNG 按钮

**要求**：
- 种子控件必须正常工作（上一个/下一个/随机/跳转/显示）
- 所有参数必须有 UI 控件
- 重新生成、重置、下载按钮必须正常工作
- 保留 Anthropic 品牌标识（UI 样式，而非艺术颜色）

## 创作过程

**用户请求** → **算法哲学** → **实现**

每个请求都是独一无二的。该过程包括：

1. **解读用户意图**——正在寻求何种美学？

5. **构建匹配的 UI 控件**——这些参数的滑块/输入框

**常量**：
- Anthropic 品牌标识（颜色、字体、布局）
- 种子导航（始终存在）
- 自包含 HTML 产物

**其他一切均为变量**：
- 算法本身
- 参数
- UI 控件
- 视觉结果

为达到最佳效果，信任创造力，让哲学指导实现。
